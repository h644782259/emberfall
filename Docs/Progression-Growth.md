# 营地进阶与阶数奖励

## 技能退点和精通核心

营地「战技」页增加独立的技能进阶退点：仅把已学 2/3 阶退回 1 阶，全部初阶、前置解锁、快捷栏和当前冷却保留。技能点仍由角色等级减去技能阶数和精通投入重新计算，反复退点/读取不会生成额外点数。原有精通重置保留，返还精通投入并关闭核心，不退技能初阶。

营地「配装方案」同时提供联合退点：一次事务退还技能2/3阶和全部精通投入，关闭核心。预览分别显示技能、精通及合计返还点数；写入失败时两部分都不改变，避免先退技能、再退精通失败的半完成状态。仍保留全部已学1阶、装备、专精、快捷栏和冷却。

精通在角色 50/65/80/95 级分别开放每方向 10/20/30/35 点上限。只能选一个核心；投入 10 点可启用初阶，20 点自动增强。每点基础属性保持原规则。

| 核心 | 真实触发事件 | 初阶 / 增强 | 内置冷却 |
|---|---|---|---|
| 破敌 | 技能命中后 6 秒内，下一次确认命中的普攻 | 追加一次非暴击攻击，20% / 35% 当前攻击 | 6 / 4 秒 |
| 生命 | 实际受伤后生命低于 50%，且仍存活 | 恢复 3% / 5% 最大生命 | 12 / 10 秒 |
| 坚壁 | 真正的完美闪避 | 15% / 25% 减伤，持续 2 / 3 秒 | 8 / 6 秒 |
| 技巧 | 成功主动技能累计实际消耗 60 / 45 能量 | 回复 8 / 12 能量，所有技能剩余冷却减少 0.4 / 0.7 秒 | 8 / 6 秒 |

技巧冷却中不累计消耗，超额不结转；资源回复不会再次触发自己。破敌用递增施法 ID 去重，持续伤害/旧命中不会反复武装同一次追加攻击。死亡命中不会触发生命核心复活。运行计数不进入存档，角色/房间战斗代次、核心或初阶/增强状态切换时清除；普通金币/背包通知不会刷新核心冷却。

`MasteryCoreRuntime` 只返回有界效果，具体战斗钩子由 PlayerController 消费；纯规则测试与战斗接线验证应分别执行。

## 实际阶数奖励

奖励按实际完成的阶数记录，不读下一次菜单选择。阶数分档：1–4、5–9、10–19、20–39、40–100。

| 项目 | 五档数值 |
|---|---|
| 沉星遗迹通关碎片 | 3 / 4 / 5 / 6 / 7 |
| 占点 / 突围 / 首领连战碎片 | 各自基础1 / 2 / 3，加分档0 / 1 / 2 / 3 / 4 |
| 五房远征通关碎片 | 4 / 5 / 6 / 7 / 8 |
| 宝箱基础金币 | 60–100 / 85–125 / 110–150 / 135–175 / 160–200 |
| 首领传说概率 | 8% / 11% / 14% / 17% / 20% |
| 首领史诗概率 | 37% / 39% / 41% / 43% / 45% |
| 首领机制概率 | 25% / 28% / 31% / 34% / 37% |
| 普通怪史诗概率 | 13% / 16% / 19% / 22% / 25% |
| 普通怪传说概率 | 2% / 3% / 4% / 5% / 6% |

原野默认保持第一档；普通怪的机制概率仅对史诗/传说掉落进行额外判定，为 12% / 14% / 16% / 18% / 20%。时装宝箱品质概率不变。最高档重复传说时装补偿加基础金币最多 1,000，存档校验接受该合法上限。

普通通关使用 `TryCompleteDungeonRun` 一次原子事务保存通关数、最佳阶数、金币、经验、等级、碎片、宝箱阶数和首通自选资格。当前通关收据重复提交不写文件、不再发奖。失败由宿主持有未结算收据重试；不要先调用旧的逐项加金币/经验方法。已有未开启/未收起宝箱不会被新收据替换。

## 已知机制的传说升华

通关沉星遗迹第 5 阶后，在营地穿戴本职业已登记配方的史诗机制装备，可以花费 24 碎片升华为传说。保留物品 ID、名称、等级、机制、锁定状态、元素变体、变体解锁和永久部位强化。现有基础属性按 25/18 确定性向上取整后应用原部位强化，上限不变。没有随机重抽，不会重复升华，也不自动替换其他装备。

退点、核心选择、升华、通关结算都先构造候选存档，写入成功后才公布内存与事件。旧存档没有宝箱阶数时按 1 阶处理；合法旧精通投入/20 点核心保留。没有加入自动清理。

## 两份角色内配装方案

每个角色固定两份、独立版本号的方案；旧存档迁移为空位，不在读取时写文件。方案记录技能阶数、四向精通与核心、元素专精、召唤路线、快捷栏与按键、穿戴的武器/护甲/饰品稳定编号。装备只保留引用，不保存物品副本、金币、经验、药剂、材料、时装或永久部位强化快照。

- 只能在营地记录、覆盖或应用；界面先预览并确认覆盖/应用。方案与角色存档不是同一列表，不会创建额外角色文件
- 应用前检查当前职业、等级、已有技能解锁、精通上限、核心门槛、共享点数、有效快捷栏及当前背包里的装备编号。错误或未来版本方案不被自动“修好”后应用，当前配装与文件保持原样
- 保存方案后新学的1阶永远保留，应用旧方案时会计入这些点数。如果因此超过当前预算，整个操作拒绝，需升级或重新记录方案
- 装备已出售、移出背包、部位不符或等级不足时，应用拒绝；同名新装备不能代替原编号。原方案保留，可查看或明确覆盖。换装应用当前永久部位强化，装备后来升级/升华/切换变体的状态不回滚
- 保存与应用均为单次候选存档事务；失败可重试，重复应用不生点、不复制物品、不重置技能冷却。应用不会领取奖励或恢复过去的货币/经验
- 格数固定为2；多出已填入方案的异常文档会被拒绝，而不是静默删掉。整个角色仍使用原4 MiB上限及一主一备存储方式

## 测试

`ProgressionGrowthTests` 用纯逻辑和独立临时存档覆盖触发隔离、冷却、非法数值、施法去重、技能共享点数、10/20 点迁移、升华失败/重试/重复调用、ID 与变体保留、阶数概率及普通通关原子收据。`ProgressionGrowthSourceTests.py` 检查交易与营地接线。使用旧 Progression/UpgradeProgression/RebalanceProgression 套件作回归。

`BuildPresetTests` 直接调用生产服务，覆盖四职业双方案往返、联合退点与保存/覆盖/应用失败回滚、新1阶保留及预算不足、缺失装备/同名不同编号、当前部位强化、非法数据拒绝、旧档迁移与已删除角色禁止复活。

没有使用用户存档。源代码/API 编译与这些测试不代表 Unity 画面、设备操作或实际战斗执行验证。
