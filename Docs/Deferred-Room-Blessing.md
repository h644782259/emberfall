# 首房祝福的原子伤害边界

首房猎杀/占领完成时，`OpenRoomGate`只记录一次房间身份、战斗epoch和请求frame，不在伤害回调中暂停。已开始的同帧链电、范围命中和其他伤害事件完整执行；后续有效的session tick（且不是请求所在frame）才打开祝福并暂停。不是简单break链电，因此不会丢失剩余跳数或重放已命中预算。

待选请求仅一个，重复目标回调不会推迟或覆盖；暂停时保留，死亡/失败/退出取消，房间身份或epoch变化拒绝旧请求。请求期间禁止进入下一房，防止同帧入口输入跳过第一次祝福。第二处休憩室祝福流程和所有技能冷却保持原有行为。

定向验证：18项请求/同帧六跳预算/下一tick/暂停/重复调用/epoch/房间替换/死亡退出规则断言；7项host接线检查；旧房间祝福接线检查；完整runtime参考API编译零警告零错误。未运行Unity真实链电或触屏操作，不将托管模拟声明为引擎复现。
