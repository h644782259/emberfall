# Live tactical support, capture and guardian feedback

Corridor and chapter supply visuals previously spawned detached rings every 0.8 seconds with a 0.85-second lifetime. Those rings could outlive support loss or remain behind a moving enemy. Each spawned tactical enemy now owns one fixed visual component: a supplier/hunt crown, a supported ward and a contender foot marker. LateUpdate reads the same session support/contest queries used by combat and capture. Lost support immediately removes the blue ward state, with a thin grey 0.24-second severance trace; the trace is not a support indicator. Dead, inactive or obsolete-epoch owners hide all three renderers. Each component owns and destroys one material.

Objective objects own twelve fixed arc segments. Their completed fraction derives from actual seals plus current capture time, divided by the existing one/two-stage objective. Completed segments turn orange while contested. Enemy foot markers use the same radius/LOS contest predicate that pauses capture. Chapter capture now invokes its public predicate directly. Neither capture durations nor enemy counts change. Renderers are allocated at attachment, not every update; no device frame-time improvement is claimed.

Ordinary guardian front armor now shares `GuardArmorRules` between the existing damage calculation and visual state. The original condition is unchanged: non-boss guardian, not preparing, incoming flat direction squared greater than .01 and front dot greater than .45 gives multiplier .65. Front armor seams open and expose a core during preparation, and close when preparation ends. An actually reduced hit flashes the armor; a hit during the open state flashes the core. “Weakpoint” here means the existing 35% frontal reduction is absent, not a new damage bonus. Bosses are excluded.

`Tests/TacticalLiveVisualTests.py <dotnet>` runs the actual three visual components and actual EnemyController damage prefix/property with explicit managed Unity substitutes. It checks object-following, no duplicate relation attachment, immediate support loss, short-feedback expiry, epoch/disable cleanup, capture segmentation, owned-material disposal, and closed-front/windup/recovery/rear/boss damage behavior. Mandatory mutations retain the stale supported display or force permanently closed armor; each must fail the production component assertions. Static contracts check removal of the old room/chapter heartbeat ring producers and guardian initialization attaching its component.

These are managed lifecycle, state and arithmetic checks, not Unity rendering, physics, device performance or visual-quality acceptance. Aggregate tests and native Unity API checks remain separate validation.
