# 传送门实体与端点状态

`WorldPortal3DVisual` 使用独立磨损石块、11 块拱券、深门侧和贴地门槛构成 1.12 米纵深的通路。石面沿用 `NaturalSurfaceAtlas`、`NaturalSceneryMeshLibrary` 与实际场景光照。门内是闭合、前后弯曲的三维体积，`PortalVolume` 在该体积内采样流动密度和深度色；它填满门洞，不再依赖细发光圈、平板或掉落光柱。18 个实体微粒合批为一个动态 mesh，并以吸入加速度、阻尼和旋转偏流运动。局部灯将门内光落在门槛与地面。

实际交互继续由原 `GameSession` 判定；外观组件只记录既有中心、半径并跟随解锁状态：

| 端点 | 真实中心 | 真实交互半径 | 光幕状态 |
| --- | --- | ---: | --- |
| 原野与城镇副本入口 | `(0,0,11)` | 4.3 | 开启 |
| 连房及战术房前向出口 | 实际 `DungeonPoint(0,0,14)` | 3.8 | 原 `roomExitMarker` 解锁时开启 |
| 章节前向出口 | `chapterPlan.Exit` | 3.8 | 原 `chapterExit` 解锁时开启 |
| 普通、挑战及首领场地通关返营 | `TryReturnPortalPosition` 实际结果 | 3.5 | 原返营条件成立时开启 |

锁定北口保留暗石框，光幕、吸入微粒与接地光一起关闭。原本只有到达用途的遗迹南口 `(0,0,-16)` 保持暗框，避免表示一个尚无交互动作的传送端点。狭窄返营 fallback 的 0.85 米是选址净空：它缩小外观，真实交互半径仍为 3.5 米。中心、交互判定、导航地图、伤害规则和传送目的地不由这些外观改写。

原生入口为 `Emberfall.Editor.WorldPortalAppearancePreview.Run`。它使用实际 Main 场景、WorldBuilder 工厂、实际安全选址和原生 marker `OnEnable/OnDisable`，拍摄营地与两个城镇入口、连房/战术/章节锁定和开启出口、普通/挑战/首领返营口及狭窄 fallback 的近远图。它验证完整门洞内像素变化、实际闭合 mesh、有限顶点、相反边方向、正体积、通行中心与原交互半径。章节按照实际房数与 `ChapterRoomPlan.Layout` 枚举；星平台仅使用真实布局 105。

微粒拓扑读取实际运行 mesh：18 颗各 6 顶点、8 三角，共 108 顶点、144 三角；每个三角仅引用同一颗粒，最长边小于 0.05 米。检查能检出跨颗粒的错误索引，避免门内出现不属于物体的长细三角。

同一原生检查会拍摄 `Camp-Court-Rug-Near.png`，读取最终营地石庭/地毯 mesh 的闭合性、实际材质与父场景灯，并对照石庭 0.0425 米、地毯 0.056 米的实际支撑高度。输出保存在 `ArtSource/Review/Portals-时间戳/`。工具和源编译通过并不等于截图视觉通过；桌面原生结果与设备上的运行、操作和帧率证据分别记录。
