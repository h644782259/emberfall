# Collection preview: compact viewport and local orbit

The mobile mannequin uses `MobilePanelLayout.BodyLeft` as its entire image and native viewport. View, action and rotation controls occupy the top of the **right-hand detail scroll content**, generated by `CollectionPreviewLayout.Mobile`. The text and restore button follow the control bank and remain scrollable; the compact first screen does not promise to display the complete description.

For 568 × 320 touch units (TouchRatio 1):

| Region | X | Y | Width | Height |
| --- | ---: | ---: | ---: | ---: |
| Model viewport | 16 | 68 | 216 | 188 |
| View controls | 252 | 76 | 282 | 48 |
| Action controls | 252 | 130 | 282 | 48 |
| Rotation controls | 252 | 184 | 282 | 48 |

View/action buttons are 90 × 48; rotation buttons are 138 × 48. All eight fit initially in the right viewport and none overlaps the model. This replaces overlay controls; the former 26-unit full-width clear strip was not the total unobscured image area.

Desktop reserves a 138-unit lower control bank plus a 6-unit gap. A 270 × 365 frame therefore has a 270 × 221 model viewport. `SetViewport` and `GUI.DrawTexture` consume this same rectangle; texture drawing uses `ScaleToFit` for every composition. Receipt previews keep their whole supplied rectangle and add no controls.

The existing 120-second presentation time remains unchanged for idle and cloth sampling. Mechanical orbit angle now independently accumulates at 16°/s modulo 360, passed from `CollectionPreviewMotion.OrbitYaw` into the actual model sampler. The 12°/s floor ring already completes four full rotations per 120 seconds. Framing samples use a static orbit; animation uses the independent angle.

Validation uses actual extracted `DrawCollectionModel` and `DrawCollectionControls` methods with GUI/render stand-ins: compact/mobile scales, all eight rectangles, image/native viewport equality and desktop separation. Compiled mutations restore overlay controls or an oversized native viewport and must fail exact assertions. The existing pose suite now advances the real motion clock across its 120-second wrap and observes the model's actual mechanical-orbit transform; restoring `time * 16` must fail continuity. These are managed geometry, quaternion and lifecycle checks, not Unity rendering, touch-device or GPU acceptance.
