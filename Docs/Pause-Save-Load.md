# 暂停菜单的保存与读取

Windows 与移动端使用居中的暂停菜单，只有一个「保存」入口。原「另存为新存档」按钮不再出现在暂停页或移动端更多设置页；新角色仍在创建时获得独立编号。

## 手动保存

点击「保存」先显示当前职业、等级和完整存档编号，明确说明将覆盖这份角色进度。确认后才调用保存，失败停留在确认页，可重试或取消；同一请求的重复点击不会再次写入。

确认页始终说明：自动保存仍持续写入当前角色，取消只取消本次手动保存。取消按钮/Esc 本身不执行保存、不创建新文件、不切换角色，返回暂停菜单。正常退出、后台生命周期和定时自动保存继续使用当前角色的编号。

## 从暂停页读取

「读取存档」打开与标题页相同的稳定编号列表。列表返回/Esc 回到暂停状态，不恢复战斗。选中角色后明确选择：

1. **保存并读取**：先将当前角色的变化、地面战利品和可结算模式奖励保存到当前编号，再读取目标
2. **放弃未保存并读取**：不保存当前角色尚未写入磁盘的变化，清理地面战利品及本局临时状态；存在待保存挑战奖励时也明确提示会放弃它
3. **取消**：不执行保存或读取，回到暂停中的选择列表

已经自动保存的内容不会因为选择「放弃未保存」而回滚。读取后重新建立营地中的目标角色，不延续旧副本怪物、延迟攻击、祝福、地面掉落或模式奖励。

确认绑定源角色和目标的完整编号。目标编号或文件元数据改变需要取消后刷新、重新确认；不会凭排序索引改读另一个角色。重复触摸还有短时/触点释放保护，不会从一个关闭的确认页穿到下一屏按钮。

## 切换时的数据隔离

实际生产 `SaveSlotTransition.TryStage` 先用独立进度服务读取/校验目标；坏档、缺档、非法路径只返回错误，不改当前玩家、源角色文件和事件订阅。选择同一角色时，「保存并读取」使用刚保存的状态，「放弃未保存并读取」使用上次磁盘状态。

目标有效且用户已作选择之后，才停止旧会话并清理临时对象。先令旧会话不再活动，清空掉落，停止协程，销毁旧玩家/怪物/世界，重置远征。远征重置经过 `ResetArenaMode(false)`，同时 Dispose/null 当前竞技模式与房间链，避免旧奖励被结算到新角色。

旧进度的游戏/界面事件订阅迁移后才发布目标服务；读取目标的 `Changed` 事件不会被旧玩家误判为换装而写回。加载营地时使用 `loadingSaveSnapshot` 保护，不额外保存刚读出的快照；后续正常自动保存只写目标角色。

## 验证

- `SafeSaveFlowTests` 使用唯一临时目录里的假角色，检查取消无写入、命名覆盖、重复确认、源/目标变化、读档预检隔离、坏档/备份、同档保存/放弃差异、真实临时目录写入失败及异常重试
- `SaveFlowSourceTests.py` 检查暂停入口、确认遮挡、自动保存提示、无保存丢弃路径、旧事件解绑、竞技/房间链清理及营地快照写入保护

这些测试不是 Unity 引擎交互或真机触控验收。
