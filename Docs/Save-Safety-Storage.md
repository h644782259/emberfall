# 角色删除与存储边界

## 删除流程

- 在标题页打开「继续冒险」，选择角色，再点击「删除角色…」；游玩中不直接删除当前角色
- 列表以稳定存档编号选择角色。确认页再次显示职业/等级、保存时间与完整编号，同职业、同等级角色不会因排序变化而误删
- 确认页明确提示无法撤销，并删除所选角色的主存档、对应 `.bak` 与 `.tmp`。其他角色、未知后缀文件、子目录、用户另行复制的外部备份不受影响
- 「取消 · 保留」或 Esc 返回列表，不改文件。默认键盘焦点落在取消，不落在永久删除
- 若确认后存档内容改变，服务拒绝删除，必须刷新并重新确认；不会按列表索引猜测目标
- 损坏存档、仅剩备份的存档及旧版 `legacy` 存档也可明确选择删除
- 删除上次使用的角色会断开其自动保存目标；不会自动读取另一角色。删除最后一份后可创建新角色；重复点击或重复提交同一完成请求不会继续删除

## 中断与失败

删除先写入并 flush 一份固定命名的 `.delete-pending` 标记，再移除该角色文件，最后移除标记。正常成功不留下累积的删除记录。

若删除时断电或权限异常，剩余数据与标记保持在原位置，列表显示「删除未完成」，不会通过备份恢复成可玩的角色，也不会被自动保存重新创建。用户需要再次确认删除，才清理剩余文件。程序不自动完成失败删除，也不扫描删除目录。

同名目录或链接会阻止删除准备，不会递归删除目录或操作链接目标。已载入角色若被删除或移走，所有持久化写入入口都会拒绝重建旧文件；必须明确创建新角色或读取其他存档。

## 容量策略

- 新建角色与保留的显式快照服务API（兼容/测试用途，暂停菜单不显示另存按钮）共享 **64 份角色上限**；达到上限会提示用户自行决定保留什么，绝不自动淘汰最旧角色
- 手动导入导致超过 64 份的原有文件继续可见、可读取；仅阻止继续新建。此上限不声称能够约束用户手工复制、外部日志或操作系统生成的文件
- 每份新写入 JSON 最大 **4 MiB**，写入前检查；超限不会覆盖主文件与备份
- 普通保存只使用一份主文件、一份轮换备份和至多一份写入中的临时文件，不产生带时间戳的无限历史
- 成功删除会移除本次删除标记；中断后保留的标记计入64份上限。新建文件在主存档/备份提交前被进程强制终止，可能留下仅有 `.tmp` 的孤立恢复文件；规范命名的临时文件也为新建容量保留一个编号，与同编号主/备文件去重计数，但不被当作可读取角色，也不会自动删除。达到容量时提示先备份目录再处理恢复文件。未知后缀、手工导入和系统文件仍不受绝对字节上限约束
- 失败时只尝试清理本次写入拥有的临时文件；不清扫其他文件，不删除有效恢复备份
- 如果发现可读取的中断 `.tmp`，保留它并阻止覆盖。用户应先备份整个存档文件夹，再处理恢复文件；程序不会默默丢弃潜在更新的角色进度，也不会自动创建重复角色绕过保护
- 保存前拒绝主文件、备份、临时文件或删除标记中的链接路径，含悬空链接；不会沿损坏的 `.tmp` 链接写入其他文件。此检查不改变或移除链接，也不宣称能锁住其他进程对目录的并发修改
- 同一种自动保存错误只记录一次，避免每个自动保存周期重复写警告；成功保存后允许下一次新错误提示
- 已有系统消息列表最多 32 条，图标与音频缓存沿用有限目录。Unity 自身日志、编辑器 Library/Temp 和发行构建由引擎/工具管理，不对它们宣称运行时硬上限

本策略不删装备、不清空待领取/恢复栏、不回收玩家收藏。原有数量边界继续拒绝超量而保留原存档。

## 验证范围

`Tests/SaveDeletionTests.cs` 直接运行生产 `ProgressionService`，仅创建唯一的临时测试目录。覆盖取消不变、重复/活动/最后一份删除、同职业排序、坏档/仅备份/旧档、确认内容变化、跨目录与路径穿越、链接/同名目录、中断后重启和再次确认、固定备份数量、64 份上限、手动导入超限、失败临时文件清理以及有效临时文件保护。

纯逻辑测试以 .NET 8 的 JSON 适配替换 Unity JsonUtility。编译检查与这些测试不能替代 Unity 真机点击、iPhone 触控尺寸实测或实际平台打包验收。
