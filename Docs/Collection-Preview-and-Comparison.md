# Equipment comparison and real-model collection preview

Inventory keeps the attack/defense/health before-and-after values and adds persistent mechanism **gained / lost / retained** labels on desktop and touch layouts. Class/slot-incompatible mechanisms are explicitly inactive; unlocked A/B variants count as different mechanisms. Desktop descriptions use a measured scroll area below the fixed numerical comparison, so the decision no longer relies on hovering. Existing slot-upgrade preview values, level gates, locked-item sale protection and service mutations are preserved.

Collection now uses an isolated `CombatModel.Hero` with the real equipped armor/weapon/relic and `ApplyFashion` appearance. Desktop shows a character beside the catalogue. Mobile has a full-body preview view with fixed 48-unit rotate/action targets and a separate scrolling catalogue. Any rarity can be tried, including unowned appearances; only owned appearances can be equipped, through the existing service. Trial objects never enter the inventory or save. Worn, owned/unowned and strongest-collection attribute source are shown separately. Wing previews start from a rear three-quarter angle, weapons from a front three-quarter angle; rotation controls turn 45 degrees without changing player/camera orientation.

Fashion chest reveals use the persisted receipt slot/rarity to dress the same real model, including duplicate receipts. Gold-only receipts keep the chest/gold presentation and never invent a fashion reward. This replaces the generic wing/weapon glyph, not the durable grant/acknowledgement logic. No reroll occurs during preview, reopen or skip.

The preview has one active mannequin, one disabled camera, one preview-only light and one 384×480×16-bit-depth render texture, rendered only during IMGUI Repaint at up to 30Hz. All preview colliders and behaviours are disabled; the stage is placed away from gameplay with a dedicated camera/light layer. Character construction saves/restores Unity random state. Inactive previews release their render texture/stage when the panel is hidden, paused, disabled, destroyed, backgrounded or the player changes. Geometry/material lifetime follows the real model's destruction cleanup. Framing is rotation-invariant to avoid zooming in/out while turning. No platform/font/iPad settings or progression-service code changed.

Validation: Presentation checks cover every hero/mechanism/slot combination, A/B changes, empty slots, exact durable reward identity, gold-only receipts, independent trial data and ownership/source labels. Source contracts check integration. These code/API checks do not establish Unity 6000.6.3f1 execution or visual acceptance.

Still require real Editor/device verification: material/shader import, the isolated camera on the selected render pipeline, framing of every class/wing/weapon, 568×320 and iPad readability/touch operation, reward reopening/duplicate presentations, and actual GPU/memory performance. The preview automatically uses future production model/wing geometry improvements; this change itself does not redesign those meshes.
